# Food vision usage telemetry

When OpenAI returns token usage, the server attempts one structured `[kcalcue:food-vision-usage]` event immediately after the provider response, before parsing or validating the food JSON. A malformed but potentially billable response can therefore appear. The event contains only an allowlisted public model family, analysis contract version, nonnegative input/cached-input/output/total token counts, and local elapsed milliseconds. It contains no image bytes, food names, prompts, account identity, request ID, credentials, or response text. Unknown model IDs or malformed counts become `null`; a throwing log sink is ignored so analysis cannot fail or retry because of telemetry.

The event is observability, not a bill: provider usage may be absent, timeouts have no response usage, prices and cache rates can change, and this does not prove whether an uncertain request was charged. Do not use these logs alone to switch models or claim a production cost reduction. Existing admission quotas and retry guards remain the cost protection. No production log sink, retention policy or model setting changes in this PR.

Local verification covers an invalid JSON response with usage, safe field logging, prefixed key-shaped/private model strings, negative/nonfinite counts, missing usage, provider transport failure, a throwing log sink, provider tests, typecheck, lint, build, emulator and browser checks. Production acceptance should confirm the field allowlist and actual usage availability with only the designated QA account after a separately authorized release.
